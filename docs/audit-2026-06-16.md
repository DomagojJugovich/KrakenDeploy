App-wide audit for unfinished/broken work, stubs, and quality cleanups, run before continuing feature work. ~68 findings across 8 slices (pages, dialogs, process editor, services, transport/agent, recent Space-in-URL diff). Safe, high-value items were fixed in the same pass (see below); the rest are triaged here by priority.

> Compilation of all fixes is verified (0 `CS`/`RZ` errors). A clean output build requires the local dev server to be stopped (it locks `src/KrakenDeploy.Server/bin`). The `.cs` changes need a server restart; most `.razor` changes hot-reload.

## Fixed in this pass

### Broken functionality
- **`Deployments.razor` / `DeploymentDetail.razor`** — added missing `@rendermode InteractiveServer`. Both pages rendered as static SSR, so their toolbars, filters, row-click navigation, tab switching and offline-result upload were entirely dead.
- **`ProcessPages/Process.razor`** — the "Create Release" toolbar button had no `Click` handler. Wired it to open `CreateReleaseDialog` (mirrors `Dashboard`/`Releases`).
- **`AddTargetWizardDialog.razor`** — `CopyTokenAsync` claimed "✓ Copied to clipboard" without copying. Now writes via `navigator.clipboard.writeText` with a warning toast on failure. The "Create target" button silently returned on a permission-deny; now surfaces an error notification.
- **`CreateReleaseDialog.razor`** — silent `return` on permission-deny now sets an error message.
- **`Tenants.razor`** (root) — tenant delete had no confirmation; added a `Dialog.Confirm` (mirrors `Environments`).

### Authorization re-checks (UiActionGuard pattern)
- **`ApproveAdhocIterationDialog.RejectAsync`**, **`Admin/License.ActivateAsync`** (`ConfigureServer`), **`CreateStepTemplateDialog.CreateAsync`** (`StepTemplateCreate`) — added the server-side `Guard.AllowAsync` re-check their siblings already perform.

### Data integrity
- **`ProcessService.AddStepAsync` / `UpdateStepAsync`** — structural validation now runs **before** persisting (in-memory), so an invalid step tree (cycle / leaf-with-children / group-with-leaf-config) is rejected without writing a corrupt row. Was: save-then-validate, leaving an invalid row in the DB. (Used in-memory validation rather than a transaction so the in-memory test provider still works.)
- **`DeploymentService.CreateAsync`** — the primary `targetId` existence check was only run for multi-target deployments; now validated unconditionally so a bogus/cross-Space id fails fast with a clear message instead of opaquely at dispatch.

### Cleanups / unifications
- New `Components/UiHelpers.cs`: shared `KrakenText.Initials(...)` (replaces 3 copies in `MainLayout`, `Dashboard`, `ProjectPages/Tenants`) and `DeploymentStatusVisuals.Icon/CssClass(...)` (replaces 2 copies in `Dashboard` + `Projects`).
- Extracted `VariableService.ToDto(...)` (was duplicated verbatim in `GetVariablesAsync` / `GetVariablesInSetAsync`).
- Deleted dead files: `Agent.Transport/Class1.cs`, `Dialogs/SchemaDrivenStepFormDialog.razor` (orphaned, superseded by `StepFormDialog`).
- Removed dead `_grid` `@ref` in `StepTemplates.razor`; removed redundant `catch (ArgumentException)` in `SubscriptionEditDialog`.
- Renamed `Variables.razor` `Open*Async` methods that were actually synchronous (`void`).
- Corrected stale comments/labels: `PackageUploadDialog` (100 MB → 500 MB), `StepPackageLoader` ("placeholder" signing → implemented RSA-SHA256), `SubscriptionHistoryDialog` empty-state (referenced a non-existent "Send test event"), `Users.razor` duplicate "Email" column title → "Email status", `TeamDetail` scope badges now show names instead of truncated GUIDs.
- `Targets.Recompute` returns a fresh list consistently; `SpaceScopedComponentBase` no longer recomputes the accessible-Space set twice on the cross-Space redirect path.

## Deferred — prioritized

### P1 — Correctness / architecture (need a design decision)
1. ~~**Agent transport-mode selection is dead**~~ — **RESOLVED 2026-06-16** via the SignalR-only consolidation. Direct/Polling were removed and the agent's `IServerLink` factory now always returns `SignalRServerLink`, so the resolution-order bug no longer exists.
2. **Auto-update only swaps the apphost exe** — `Agent/Services/AgentUpdateService.cs:248`. The agent isn't published single-file, so the new exe loads the *old* managed DLLs → update is a no-op or bricks the agent. Fix: copy the whole staging dir, or set `PublishSingleFile=true` for the agent.
3. **Server-script log sequencing race** — `Server.Transport/ServerScriptStepRunner.cs:235`. Bypasses `LogSequencer` and does an unguarded `NextLogSequence++` per line; parallel server steps in a wave produce duplicate/out-of-order sequence numbers (the `(DeploymentId, Sequence)` index is not unique). Also an unlocked `List<Task>` written from process-pool threads. Fix: thread the per-deployment `LogSequencer` / `AppendConcurrentLogAsync`.

### P2 — Unfinished features / visible placeholders
- **Placeholder pages wired into nav** (`ProjectPages/`): `Triggers`, `Runbooks` (+ `RunbookTriggers`), `EphemeralEnvironments` are **primary** project tabs that land on a "— pending" alert; `VariablePreview`, `AllVariables`, `TenantVariables` are Variables sub-tabs in the same state. Decision: implement, or hide the tabs until built.
- **Service accounts are a dead-end** — `NewServiceAccountDialog` creates an account, but API-key issuance ("coming in M13.C.4") doesn't exist, so the account can never sign in. Hide the button or build key issuance.
- **`DeploymentDetail.RegenerateAsync`** toasts "Re-generating…" but only `await Task.CompletedTask`. Either wire real regeneration or change the copy to the honest instruction.
- **Offline-drop Email delivery** — `DeploymentWorker.cs:805` logs "not yet implemented" and drops the bundle silently. Implement SMTP or disallow selecting Email at config time.
- ~~**Polling/Direct transports**~~ — **REMOVED 2026-06-16** (SignalR-only). Deleted `DirectServerLink`/`PollingServerLink`, their `TransportMode` enum members, the wizard radios, and the server-side REST mirror endpoints. Air-gapped targets keep using OfflineDrop.
- **`Process.razor` Script Modules card** is a permanent placeholder with a disabled Include button; the per-step "Runs for any environment" caption is hardcoded.
- **`OctopusSystemVariablesBuilder`** emits empty strings for several data-backed keys (`Deployment.CreatedBy.*`, `PreviousSuccessful.*`, `Release.Channel.Name`, etc.) — imported Octopus scripts reading them get `""`.

### P3 — Quality / performance
- **N+1 queries**: `Packages.ReloadAsync` (comment falsely claims "in parallel"), `ProjectPages/Variables.ReloadAsync`, `ProjectPages/Tenants.ReloadConnectedAsync`. Add batched service queries.
- **`DashboardService.GetSummaryAsync`** runs 6+ independent reads sequentially on one context (Home landing page). Fan out over short-lived contexts if latency matters.
- **`FormatBytes`** duplicated across 6 files (one variant omits the GB tier) — extract one formatter (next to `KrakenText`).
- **`ConfigureAwait(false)` sweep** — several `Server.Data` query methods (`ReleaseService.GetAsync`, `DeploymentService.Get*`, `TargetService.GetAllAsync`) omit it; harmless but inconsistent with the layer convention.
- **`GrpcPackageDownloader`/`GrpcStepPackageDownloader`/`GrpcArtifactUploader`** set `Http2UnencryptedSupport` unconditionally (triplicated) — gate behind one shared dev-only flag (relevant for GDPR/sektorski hygiene).
- **`PostgresAgentConnectionRegistry`** writes the `agent_connections` table on every connect/disconnect but never reads it — dead I/O and an unfulfilled HA-lookup promise. Drop the backing or finish cross-node lookup (needs a SignalR backplane).
- **`AgentHub.ReportStatusAsync`** ignores the agent's `ShuttingDown` signal, so a stopped target shows Online for the 30s grace.

### P4 — Redesign / theming (the wider redesign pass)
- List pages still on the old `RadzenStack`/`H5` header instead of the redesigned `page-head` chrome: `Lifecycles`, `VariableSets`, `Runbooks`, `StepTemplates`, `StepPackages`, `Tenants`.
- Detail pages with ad-hoc headers vs `TargetDetail`'s breadcrumb/`page-head`: `LifecycleDetail`, `VariableSetDetail`, `RunbookDetail`, `TenantDetail`.
- Hardcoded hex colors that ignore the deep-sea/coral theme (break in dark mode): `RunbookDetail` log panel (`#1e1e1e`), `ApproveAdhocIterationDialog` / `AdhocSessionDetail` (`#f5f5f5`, `#b00020`). Replace with Radzen ramp / Kraken surface variables.
- `SubscriptionEditDialog` runbook Target is a free-text GUID box while every other reference uses a name dropdown.
